# Портфолио Ярослава

Двуязычное портфолио AI-разработчика в пиксельном стиле: Next.js App Router, React, TypeScript и Tailwind CSS. `/` перенаправляет на `/ru`. Видео в hero открывает и закрывает ноутбук при прокрутке. Инструкция для VPS, домена и автоматического HTTPS: [docs/deployment.md](docs/deployment.md).

## Админка

`/admin` — вход через Supabase Auth, создание и редактирование проектов, RU/EN, загрузка обложек, черновики, публикация, порядок, фильтры и удаление. Изменения на сайте не требуют пересборки. Доступ к данным ограничивается RLS и списком назначенных администраторов.

Локальный сайт и публичный VPS получают актуальные данные из восстановленного Supabase. На VPS включён `SUPABASE_NETWORK_MODE=short-connections`: чтение проектов использует отдельные соединения с повтором прерванных запросов, обложки загружаются частями через HTTPS и сохраняются в Docker volume. VPN не используется. Для настройки таблиц и доступа используйте [инструкцию подключения](docs/admin-setup.md). В исходниках нет ключей, паролей или обхода авторизации. До подключения `/admin` показывает шаги настройки.

## Локальный запуск

Требуется Node.js 22+.

```sh
npm install
npm run dev -- --port 3001
```

Откройте [русскую версию](http://localhost:3001/ru) или [английскую версию](http://localhost:3001/en). Порт 3001 выбран, чтобы не конфликтовать с другими проектами на стандартном порту 3000.

При настроенных локальных переменных Supabase команда выше показывает актуальные опубликованные проекты. Если Supabase недоступен при `npm run dev`, отображаются три локальных демонстрационных кейса: forma, pulse и spot. Они подписаны как концепты. В production ошибка базы показывает сообщение с повторной загрузкой.

Production-режим:

```sh
PROJECTS_SOURCE=supabase npm run build
PROJECTS_SOURCE=supabase npm run start -- --port 3001
```

## Изменение материалов

В режиме Supabase опубликованные проекты редактируются через `/admin` без пересборки. `PROJECTS_SOURCE=snapshot` использует копию от 19 октября 2026 года из `src/content/published-projects.ts` и локальные обложки из `public/projects`. Последующие изменения базы в ней отсутствуют; для обновления снимка нужна пересборка. Автоматической подмены данных снимком при ошибке базы нет.

Тексты главного экрана и технологии находятся в `src/content/pixel-portfolio.ts`. Контакты и демопримеры находятся в `src/content/portfolio.ts`:

- `profile`: имя, путь к портрету и технологии.
- `copy.ru` / `copy.en`: общие подписи и тексты архивных компонентов. Текущие hero и metadata используют `pixelCopy`.
- `projects`: демопримеры, используемые только пока Supabase не настроен. Реальные карточки, видимость, порядок и признак концепта изменяются через админку.
- `contacts`: добавьте `href` и `value`. Email использует `mailto:`, Telegram и GitHub — полный HTTPS-адрес. Без адреса контакт остаётся явно подписанной заглушкой.

forma, pulse и spot — вымышленные демонстрационные концепты. Они не входят в публикацию с `PROJECTS_SOURCE=snapshot`. Сохранённые реальные работы имеют свои описания, ссылки и обложки.

Превью лежат в `public/projects` в формате SVG; их можно заменить собственными изображениями. Портрет находится в `public/images/yaroslav.webp`, исходные PNG сохранены в `images`. Manrope поставляется локально через Fontsource; запросов к Google Fonts нет.

## Поведение

- RU / EN сохраняет видимый раздел страницы.
- Карусель: стрелки, нативный свайп/прокрутка, клавиши ← / → / Home / End при фокусе на ленте. Без автоперелистывания и зацикливания.
- Появление секций и лёгкий параллакс отключаются при `prefers-reduced-motion`; параллакс доступен только с точным указателем на широком экране.
- Контент доступен без JavaScript; карусель остаётся прокручиваемой, переключение языков работает обычными ссылками.

## Проверки

```sh
npm run lint
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:admin
npm run test:db
npx playwright test --config playwright.transport.config.ts
```

`test:e2e` запускает production-сервер на порту 3100. Проверяет оба языка на ширинах 360, 390, 768, 1440 и 1920 px, переходы, metadata, клавиатуру, свайп, изменение размера карусели, уменьшенное движение и валидацию проектов. Базовые тесты демоверсии выполняются без настроек Supabase.

`test:admin` использует отдельный dev-сервер на 3101 и тестовый HTTP-сервер Supabase на 3111; `test:db` проверяет настоящую миграцию и RLS во временном PostgreSQL в Docker. Скриншоты сохраняются в `test-results`. Тесты не подключаются к облачной базе.

При публикации `SITE_URL` задаёт домен для canonical и языковых альтернатив. Caddy обслуживает HTTPS и продлевает сертификаты, сохраняя их в отдельном Docker volume. Сервер сообщений не используется; база и хранение обложек для админки предоставляются Supabase.
