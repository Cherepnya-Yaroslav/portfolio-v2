# Подключение админки к новому Supabase

Админка нового сайта доступна по `/admin`. Она использует Supabase Auth, PostgreSQL и Storage. Отдельный API-сервер, service_role key и публичная регистрация не нужны.

## 1. Создать проект и таблицы

1. Создайте новый проект в [Supabase Dashboard](https://supabase.com/dashboard).
2. В **SQL Editor** выполните содержимое `supabase/migrations/202609070001_portfolio_admin.sql`.
3. Скрипт создаёт `portfolio_projects`, `portfolio_admins` и бакет `portfolio-images`. Таблицы и бакеты старого сайта не используются.

Миграцию можно выполнять повторно: она не удаляет карточки. Включены RLS, ограничения полей, проверка обязательных данных для публикации и запрет удаления используемых обложек.

## 2. Назначить администратора

1. В **Authentication → Users → Add user** создайте пользователя с email и паролем. Подтвердите email при создании.
2. Скопируйте его User UID и подставьте в SQL:

```sql
insert into public.portfolio_admins (user_id)
values ('ВСТАВЬТЕ_USER_UID')
on conflict (user_id) do nothing;
```

3. В настройках Authentication отключите **Allow new users to sign up**. UI регистрации в приложении отсутствует; даже зарегистрированный пользователь без записи в `portfolio_admins` не получает права редактирования.

Чтобы отозвать доступ, удалите только соответствующую строку из `portfolio_admins`. RLS проверяет её при каждом запросе, а не только при входе.

## 3. Подключить приложение

В настройках проекта Supabase скопируйте **Project URL** и **Publishable key**. Старый публичный **anon key** тоже поддерживается. Не используйте `service_role` или secret key.

Создайте локальный `.env.local` в корне нового сайта:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Эти значения публичны по назначению; права доступа защищены политиками базы. Пароль пользователя не записывается в настройки и вводится только в форме входа. Сессией и обновлением токенов управляет Supabase SDK.

Перезапустите приложение:

```sh
npm run dev -- --port 3001
```

Для production необходима новая сборка после добавления или изменения `NEXT_PUBLIC_*`:

```sh
npm run build
npm run start -- --port 3001
```

Откройте [админку](http://localhost:3001/admin). Если приложение будет опубликовано на Vercel, задайте те же две переменные в настройках проекта Vercel до сборки. В Supabase Auth настройте Site URL под реальный домен. Для нового домена используйте HTTPS.

## Работа с проектами

- **Новый проект** открывает пустой редактор; для черновика достаточно названия.
- Заполните RU: категорию, описание, роль и описание обложки. Для публикации эти поля и сама обложка обязательны.
- EN редактируется отдельно. Пустое поле EN использует соответствующий русский текст; его можно перевести позже.
- Технологии вводятся через запятую. Ссылки на сайт и код необязательны, поддерживаются только HTTP(S).
- Обложка: JPG, PNG или WebP до 5 МБ. Рекомендуется заранее оптимизированный скриншот около 1600 × 1000. SVG и другие активные форматы не принимаются.
- Изображение хранится локально до **Сохранить**. При успешной замене старая неиспользуемая обложка удаляется. Ошибка очистки показывается отдельно и не отменяет сохранённый проект.
- Меньшее число **Порядок** показывает карточку раньше в карусели.
- **Черновик** скрыт от посетителей; **Опубликован** виден на обеих языковых версиях.
- **Скрыть с сайта** переводит сохранённый проект в черновик без удаления.
- Удаление требует отдельного подтверждения. Используемые другими карточками обложки не удаляются.
- Если проект одновременно изменили в другой вкладке, сохранение не перезаписывает чужие изменения: обновите список и повторите редактирование.

Публичный бакет используется только для обложек портфолио. Прямые ссылки на загруженные изображения доступны публично, включая изображения черновиков; не загружайте конфиденциальные материалы. Текст и данные черновиков защищены RLS.

## Обновление публичного сайта

При подключённом Supabase страницы получают актуальные опубликованные записи на сервере без кеширования запроса. Для публикации/скрытия проекта не нужна пересборка; достаточно обновить открытую страницу портфолио. Количество работ и порядок карусели определяются данными базы.

Без конфигурации сохраняется исходная статическая демоверсия. После подключения пустая база показывает пустое состояние, а не демопроекты. При ошибке базы сайт показывает сообщение с повторной загрузкой и не подставляет фиктивные работы.

## Проверки

```sh
npm run lint
npm run typecheck
npm run build
npm run test:e2e
npm run test:admin
npm run test:db
```

`test:admin` проверяет UI и интеграцию с тестовым HTTP-сервером, совместимым с используемыми маршрутами Supabase. Настоящие облачные данные не затрагиваются. `test:db` запускает временный PostgreSQL 16 в Docker и проверяет реальную миграцию, RLS, ограничения и доступ к Storage на минимальной тестовой схеме Supabase. Контейнер удаляется после проверки. Для выполнения нужен работающий Docker.

Для реального Supabase после подключения проверьте вход, загрузку обложки, создание черновика, публикацию, порядок, скрытие, удаление и вход аккаунтом без административных прав.
